# 미래에셋증권 연금 상담 RAG 챗봇

제10회 2026 미래에셋증권 AI Festival 예선 제출작.
제공된 연금·퇴직연금 문서(**12,417 청크**)만을 근거로 답변하는 **질문 유형 라우팅 기반 RAG 상담 시스템**입니다.

이 시스템의 설계 원칙은 하나입니다 — **반드시 성립해야 하는 규칙은 프롬프트가 아니라 코드가 보장한다.**

---

## 1. 처리 흐름

```
질문
 ├─[1] 하이브리드 검색   임베딩(의미) 0.6 + BM25(정확 용어) 0.4
 ├─[2] 임계값 필터       최고 유사도 < 0.45 → 무관 즉시 차단 (LLM 호출 없이 응답)
 ├─[3] LLM 유형 분류     제도 / 세제 / 상품설명 / 추천 / 무관   ← 무관 2차 방어
 ├─[4] 근거 필터         최고 유사도의 85% 미만인 문서는 근거에서 제외
 │                       (무엇을 왜 뺐는지 think_trace에 기록)
 ├─[5] 유형별 사전 카드   코드가 계산·판정해 프롬프트에 주입
 │      ├ 세제      → 소득·납입액 추출 → 파이썬 세액공제 계산기 (한도 600/900 상품별 판정)
 │      ├ 상품설명  → 투자설명서 원문에서 위험등급·변동성을 읽어 카드로 주입
 │      ├ 수수료    → 보수표 청크를 검색과 별개로 직접 보강 + 인용 기준 규칙
 │      └ 추천      → 성향 확인 질문 / 성향 모순(안정+공격) 교정
 ├─[6] 답변 생성         유형 전용 시스템 프롬프트 (HCX-005)
 ├─[7] 근거 검증 레이어   답변을 문서와 대조 → 불일치 시에만 교정
 ├─[8] 출처 자동 표기     [참고 문서] 파일명을 코드가 부착 (누락 불가)
 └─[9] 출력 정리         코드가 결정적으로 교정 (아래 2장)
```

모든 단계는 응답의 `think_trace` 필드에 남아, 답이 어떤 경로로 나왔는지 외부에서 검증할 수 있습니다.

## 2. 코드가 보장하는 규칙

프롬프트로 지시한 규칙은 지시가 많아질수록 지켜지지 않습니다.
그래서 **틀리면 안 되는 것**은 생성 이후 코드가 검사하고 고칩니다. 처리 건수는 모두 `think_trace`에 남습니다.

| 규칙 | 하는 일 |
|---|---|
| 세액공제 계산 강제 | 답변 속 `A만원 × B% = C만원` 을 파이썬 계산 결과와 대조·교정 |
| 상품별 한도 판정 | 연금저축 단독 600만원 / IRP 포함 합산 900만원을 질문에서 판별 |
| 공제 대상 판정 | 회사 부담금·퇴직금 이전액·ISA 전환금이 섞이면 계산기를 끄고 사유를 명시 |
| ISA 전환금 총액 | 일반 한도와 **별도로** 전환금의 10%(최대 300만원) — 총액을 코드가 계산해 명시 |
| 위험등급 원문 판정 | 투자설명서 원문에서 현재 등급을 읽고, 답변의 표·문장을 그 값으로 교정 |
| 변동성 척도 검사 | 척도가 다른 값(3년 97.5% VaR / 일간 VaR)은 나란히 비교하지 않음 |
| 문서 오표기 고지 | 원문의 단위 오기를 그대로 인용하지 않고 계산값과 함께 사실을 밝힘 |
| 순위 단정 차단 | 자료에 순위 근거가 없으면 '가장 ~한 상품' 단정을 제거하고 한계를 고지 |
| 비교표 항목 보강 | 비교 축이 빠지면 코드가 '자료 없음' 행으로 채우고 각주로 한계를 밝힘 |
| 잘못된 전제 교정 | "중도해지해도 세금 없다", "5,500만원 이하면 13.2%" 같은 전제를 문서 기준으로 정정 |
| 단일턴 대응 | 되묻기만 하고 끝내지 않고, 경우를 나눠 실질 안내까지 한 번에 제공 |

### 위험등급 — 왜 코드가 원문을 읽는가

투자설명서에는 **현재 등급**과 **변경 이력**이 함께 실려 있습니다.

```
투자위험등급 5등급[낮은 위험]                                    ← 현재
2023.12.13 위험등급 변경[5등급(낮은 위험)→4등급(보통 위험)]      ← 과거 이력
2025.12.30 위험등급 변경[4등급(보통 위험)→5등급(낮은 위험)]
```

모델은 이력의 과거 등급을 현재 등급으로 옮겨 적는 일이 있었고, 그 값을 근거로
"안정적인 상품"을 잘못 골라 추천했습니다. **전체 문서 중 6건이 이 함정을 갖고 있습니다.**

이 시스템은 답변의 표가 아니라 **해당 문서의 원문 전체**에서 등급을 읽습니다.
표기 형태가 운용사마다 달라(`투자위험등급 N등급[라벨]` / `투자 위험 등급 N등급` /
`감안하여 N등급으로 분류` 등) 다섯 가지 형태를 우선순위로 읽고,
`분류기준 표`와 `변경 이력` 구간의 숫자는 배제합니다.

## 3. 환경 구성

### 3-1. 요구 사항
- Python 3.12
- CLOVA Studio API Key (임베딩 v2 / HCX-005)

### 3-2. 설치

```bash
git clone <repository-url>
cd <repository>

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 3-3. 환경 변수

`.env.example` 을 `.env` 로 복사한 뒤 키를 채웁니다. (`.env` 는 저장소에 포함되지 않습니다)

```bash
cp .env.example .env
```

### 3-4. 인덱스 생성

대용량 산출물(`chunks.json` 23MB, `embeddings.json` 147MB)은 저장소에 포함하지 않으며 아래로 재생성합니다.

```bash
python3 ocr_scan_docs.py      # 문서 텍스트 추출 (스캔 PDF는 OCR)
python3 build_chunks.py       # 청크 분할       → chunks.json
python3 build_embeddings.py   # 임베딩 생성     → embeddings.json  (API 호출, 수십 분 소요)
```

### 3-5. 실행

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

기동 시 BM25 키워드 인덱스를 구축하므로 **최초 준비까지 약 60~90초**가 걸립니다.
아래처럼 실제 200 응답을 확인한 뒤 사용하는 것을 권합니다.

```bash
until curl -s -o /dev/null -w '%{http_code}' \
      "http://localhost:8000/answer?question_id=ping&question=IRP" | grep -q 200
do sleep 2; done; echo "준비 완료"
```

무중단 운영(백그라운드 + 자동 복구):

```bash
nohup uvicorn main:app --host 0.0.0.0 --port 8000 > server.log 2>&1 &
crontab -e   # */5 * * * * /bin/bash /root/app/watchdog.sh
```

### 3-6. Docker

```bash
docker build -t pension-rag .
docker run -d -p 8000:8000 -e CLOVA_API_KEY=<발급받은 키> pension-rag
```

## 5. 검증

고친 것이 계속 고쳐져 있는지를 매 수정마다 확인합니다. **고친 버그는 모두 회귀 항목이 됩니다.**

| 검증 | 스크립트 | 결과 |
|---|---|---|
| 회귀 — 과거 수정 유지 (46항목) | `test_regression.py` | **46/46 통과** (간헐 0 / 재발 0) |
| 위험등급 추출 + 교차검증 | `check_risk.py` | 투자설명서 **99/99 추출**, 교차검증 **62/62 일치**, 이력 함정 6건 검출 |
| 투자설명서 보수 검산 (100건·376행) | `audit_fees.py` | 구성항목 합계와 총보수 불일치 **0건** |
| 문서 FAQ 전수 시험 (237문항) | `mock_exam_full.py` | 호출 오류 0 / 검색 실패 0 |
| 허점 사냥 (조합 질문) | `test_hunt3.py`, `test_hunt4.py` | 발견된 결함은 모두 회귀 항목으로 편입 |
| 답변 일관성 (5문항 × 3회) | `test_consistency.py` | 유형 일관성 5/5 |
| 무관 판정 임계값 실험 | `test_threshold.py` | 임계값 0.45 도출 |
| 라우팅 분류 정확도 (25문항) | `test_routing.py` | 25/25 (100%) |
| 공식 참고 질의 (5문항) | `test_official.py` | 전 문항 통과 |
| 응답 시간 (10문항) | `measure_time.py` | 중앙값 5.6초 / 최대 24.5초 |

```bash
python3 check_risk.py          # 서버 없이 실행 — 실패 시 종료코드 1 (배포 게이트)
python3 test_regression.py     # 서버 기동 상태에서 실행
```

`check_risk.py` 는 판정 로직을 `main.py` 에서 그대로 꺼내 씁니다.
`test_regression.py` 도 판정 문구를 `main.py` 의 상수에서 읽어옵니다.
**같은 판단을 두 군데에 두면 반드시 어긋나기 때문입니다.**

## 7. 설계 원칙

1. **문서 기반 폐쇄형** — 외부 인터넷을 조회하지 않고 제공 데이터만 근거로 사용합니다.
   문서 내 개정 전후 수치가 충돌하면 적용 시점이 명시된 최신 기준을 우선합니다.
2. **모르는 것은 모른다고 답한다** — 문서에서 확인되지 않는 수치·상품명은 만들지 않고,
   한계를 밝히거나 판단에 필요한 정보를 되묻습니다. 단, 되묻고 끝내지 않고
   경우를 나눠 실질 안내까지 함께 제공합니다(단일턴 평가 대응).
3. **덜 자세한 답도 결함으로 본다** — 정확하기만 한 답이 아니라, 소비자가 실제로
   판단할 수 있는 답을 목표로 합니다. 비교 항목이 빠지거나 총액이 누락되면 코드가 채웁니다.
4. **모든 답변은 추적 가능하다** — 출처 파일명을 코드가 부착하고,
   `retrieved_context` 로 근거 원문을, `think_trace` 로 처리 경로를 확인할 수 있습니다.
5. **규칙은 한 곳에만 둔다** — 판정 기준을 코드와 테스트에 따로 두지 않습니다.
